黑箱，不止一层

“黑箱”是个大概念：技术看不透、自己看不清、产品不让你看。
01
技术本身的黑箱
可解释性弱
  • 模型规模变大后，会“突然”出现小模型没有的能力——“涌现”
  • 涌现是真跳变，还是评测指标造成的错觉，学界仍有争论
  • 这种能力无法从小模型的表现提前推算出来
学术研究
02
内心的黑箱
认知有限
  • 不了解原理，就不知道它会错在哪
  • 误判结果的可靠程度
  • 夸大它带来的收益
讲者观点
03
商业趋势的黑箱
封装降低门槛
  • 产品越做越“傻瓜”，过程越藏越深
  • 好用的趋势，本身就在制造一个又一个黑箱
讲者观点
三层叠在一起，就有了下一页的三个误区。

黑箱里的三个误区

产品越封装、越好用，本身就越是一个黑箱——很多误解，都从这里来。
01
幻觉，是对错问题，还是对齐问题？
  • 对的和错的答案，走的是同一套“逐词按概率生成”
  • 训练和评测只奖励“答对”，不奖励“不知道”，模型被训练成会猜
  • 偏好对齐还会让模型迎合用户（sycophancy）
→ 本质是对齐问题
02
接了法律数据库的 MCP，就能精准检索了吗？
  • 返回几条、给摘要还是全文，由服务端的工具自己定义
  • 客户端对单次返回有上限：如 Claude Code 默认 25,000 token
  • 检索怎么排序、库覆盖多全、调不调、调几次，全在黑箱里
→ 以为全部拿到了：拿回来的 ≠ 库里有的
03
交给 AI 的案件材料，它真的都读了吗？
  • 律师材料大量是二进制：扫描合同、印章图片、Excel、CAD、邮件、音视频、压缩包
  • 预处理走哪条解析 / OCR 路线带随意性，处理不好就丢信息，且不提示
  • 佐证：Claude API 单次 PDF 32 MB、通常 100 页；Word 内嵌图片不读；长材料中段易被忽略
→ 以为全读了：丢了信息也不提醒
我们的开源项目 ADG（Agent Data Gateway）就为此而做
机制可以去弄清楚；在自己的信任上建一个错误前提，后果才严重。
