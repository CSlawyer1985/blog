问题 01

前五课，其实都在讲 Agent 的哪一部分？

前五课拼成一个 Agent：动手落盘、产出多形态、模型会猜也会错、经验沉淀成 Skill，全部装进工作区。
02 / 14

约 5 分钟｜镜头拉开，地图依次长出模型、工具、核验、经验四个节点；金色标签标出前五课各自对应 Agent 的哪一部分（顺序不重要，不按课次讲）。

  • 开场一句：“前面几节课各讲了一样东西。今天不加新名词，而是把它们放回同一张图——它们都是 Agent 的视角或组成。”
  • 每个标签一句话回顾：
    • WorkBuddy 应用 · 任务 → 工具执行 → 落盘成果：认识 Agent 工作台的界面、功能和对话方式，亲手做出一份成果（如法律意见书）。关键体感：Agent 能动手操作你的电脑，把成果直接落盘在你的电脑里。
    • 可视化 · 工具与产出形态：时间图、法律关系图、律所经营数据仪表盘、案件动态交互演示（如一栋楼怎样建起来）；产出可以是 PPT、网页等多种形态。认知：凡是在电脑上做的事，都可以先让它试——原则上它能通过运行命令，完成人在电脑上能做的工作。
    • 大语言模型的聪明与幻觉 · 模型 + 核验：从图灵测试讲到今天；今天说的 AI 主要指基于 Transformer 的大语言模型，它始终在做“猜下一个词”的游戏，天然存在幻觉——所以会输出错误的法条和案例。结果必须核验，正确对待它。
    • Skill · 经验沉淀与工具连接：Skill 是什么、怎样制作；沉淀自己的经验或蒸馏别人的经验，变成可复用的指南（作业：为自己的场景做一个 Skill）。同一课也讲了接入 MCP——让 Agent 连接外部工具和数据。
    • 工作区 · 整个外圈：每类任务建一个独立工作区，里面可以有 agents 规则文件、memory 记忆文件、脚本、Skill 和各种规则；随着使用不断沉淀、检验、迭代，隐性知识显性化，最终成为专做某件事的系统。它把前几课串了起来——第 5 页会展开成外圈 Harness。
  • 指着环上流动的光点：这是一个循环——任务进来、模型判断、工具执行、结果核验、经验留下，再回到下一次任务。
  • 提醒：对应关系是教学上的简化，每节课其实都碰到了多个环节。
  • 过渡：“这张图的中心是模型。那为什么偏偏是‘语言’模型？”

问题 02

为什么是大“语言”模型？

语言是经验的重要载体，但不等于全部思维；执行交给工具，结果仍要人核验。
03 / 14

约 7 分钟（页面讲解约 4 分钟 + 网站演示约 3 分钟）｜镜头推到“模型”节点：右侧词块逐个接上，候选概率条出现，“通知”被接上；下方文字流缓慢流动；结构化数据交给“工具”。

  • 词块接龙（约 1.5 分钟）“语言模型”的本义：给定前文，估计下一个片段（token）。“合同解除应当以书面形式——通知”，大家脑中都会自动补上；概率条只是示意。与“大语言模型的聪明与幻觉”一课呼应（那节课讲过猜词机制与幻觉），不展开数学。
  • 文字流（约 1 分钟）律师行业的经验和方法大量以文字存在——法条、判决、办案手册、范本、邮件。模型学到的不只是词语搭配，也包括文字里体现的表达与推理方式。
  • 数据卡片（约 1 分钟）自然语言描述 → 模型转写为结构化内容或代码 → 工具实际执行（跑代码、生成文件）。这就是“可视化”一课背后的机制。示例数据为虚构。
  • 左侧结论句（约 0.5 分钟）：不说“语言等于全部思维”；工具执行的结果也仍要核验。
  • 网站演示（约 3 分钟，需联网）：点左侧「为什么是语言」按钮，或点地图上发光的“模型”节点——节点会展开成近全屏网站。只看三处，不从头滚到尾：
    • “机器读语言：切开、编号、看伙伴、猜下一个”——分词 → 编号 → 向量 → 预测下一个词的示意（页面注明为示意、概率为虚构）。
    • “预测下一个词，算不算理解？”——两方观点的天平：Hinton 一方与 Bender、Searle、乔姆斯基一方；强调至今没有公认答案。
    • “争的不是机器，是语言里装着什么”——形式语言与自然语言之间的“搬运”，是法律人的日常手艺。
      页面引语标有核实状态；现场不要引用标为“待核实”的句子当作定论。看完点左上“返回本页”。网络不通时用“备用说明”。
  • 过渡：“既然模型是根据前文接下去，那我们每次用 AI，到底给了它什么‘前文’？”

问题 04

我们能掌握 Agent 的哪一部分？

Agent = Model + Harness
模型决定能力上限；应用者能掌握的，正是 Harness。
05 / 14

约 8 分钟｜地图外圈 Harness（规则、上下文、记忆、脚本、Skill、MCP、检查）依次长出，金色标签标出前几课的位置；模型⇄工具之间的光点持续循环，中心写着“模型判断 ⇄ 工具执行”。

  • 内圈（2 分钟）：模型判断（下一步做什么、调哪个工具）→ 系统按权限执行工具 → 结果反馈 → 继续判断，直到完成或需要人确认。强调“按权限”：能不能读文件、能不能发邮件，是系统设定的，不是模型说了算。
  • 外圈（2 分钟）：规则、上下文、记忆、脚本、Skill、MCP（连接工具）、检查——这一圈就是 Harness（本意“挽具”），让模型的能力被约束、被引导、被检查。
  • 金色标签（2 分钟）：前几课在图上的位置——WorkBuddy 应用给了“任务 → 工具执行 → 落盘成果”的体感；可视化扩展了工具与产出形态；聪明与幻觉讲的是模型，以及为什么要核验；Skill 一课讲了 Skill 和 MCP，都在外圈；工作区一课，就是把这一整圈（规则、记忆、脚本、Skill……）装进一个独立空间。所以前几课合起来，正好从“Agent”走到了“Agent = Model + Harness”。“检查”是今天要反复强调的。
  • 核心观点（2 分钟）：不否定模型能力——模型越强，上限越高；但同一个模型在不同 Harness 里表现可以差很多。应用者最能掌握、最该投入的是 Harness。
  • 本图参考 learn-agent.legalagi.cn 的结构重新简化绘制，不展开原站 78 个节点。地图上“HARNESS”标签或左侧按钮可展开原站（需联网），建议课后自学。
  • 过渡：“Harness 里最贴近日常的是规则和上下文。下一页讲怎样把一次纠正沉淀下来。”

问题 05

怎样把一次纠正，变成下次的做法？

保存了 ≠ 下次读到；记忆 ≠ 训练模型参数。
规则 · Skill · 记忆 · MCP（连接工具的协议，不是记忆）
06 / 14

约 8 分钟｜镜头转到地图左侧：一条金线从“核验”出发，依次经过五步，最后写进“规则”；下方是“提醒 ≠ 确认 ≠ 完成”小场景卡片。四个概念屏幕上只留一行，细节在下方。

  • 五步循环（2 分钟）：类比带新助理改稿。不只改掉错字，而是告诉他“为什么这样改”，再说清“什么情况下适用”，他下次才能自己做对。对 AI 同理：看到结果 → 纠正 → 说明理由 → 提炼适用条件 → 保存复用。“默会知识”就是那些平时不说、但心里有数的标准。
  • 小场景（2 分钟）：AI 汇报“收件提醒已发出，流程完成”。错在把三个状态混为一谈：提醒 = 通知发出去了；确认 = 对方确认收到；完成 = 约定事项办结且有留痕。纠正时把区分和理由写下来，并注明适用范围（如涉及期限、送达的事项）。
  • 四个概念（2 分钟）：
    • 规则：每次都应遵守的要求（如“状态汇报必须区分提醒/确认/完成”）。
    • Skill：某一类任务的做法、模板、检查清单，需要时调用。
    • 记忆：跨对话保留的偏好或信息；各产品保存、检索、删除机制不同。
    • MCP：让 Agent 连接外部工具和资源的协议（像标准插口），能把数据接进来（Skill 一课讲过接入方法），但本身不是记忆。
  • 两个误解（2 分钟）：“保存了”不代表下次一定被读到——要看新任务里是否真的加载了它（行动四会讲怎样倒推检测）；记忆不是训练——写进记忆的是文字，对话时装入上下文，模型参数没有因此改变。
  • 过渡：“各家产品在保存、调用上差别很大，那我们怎么看 AI 产品？”

问题 06

选 AI 产品，该看形态还是看排名？

懂原理，换产品也能迁移。复杂 ≠ 更好，命令行 ≠ 更专业。
07 / 14

约 7 分钟（含网站 2—3 分钟）

  • 开场：“市面上的产品很多，今天不讲清单、不做排名，只讲怎么看形态。”
  • 三层形态圈（2 分钟）：地图上由内到外圈出问答 → 任务工作台 → 长期助理。拿问题 05 那条“提醒/确认/完成”的经验，放进三种形态比较：
    • 问答型：经验常常只留在这次聊天里，换个对话就没了（部分产品有记忆功能，效果要实测）。
    • 任务工作台：可以写成规则文件或 Skill，按任务加载；文件看得见、改得了。
    • 长期助理：能跨任务持续带着经验，但也更需要定期回看是否过时。
      说明这是常见情形示意，不是对具体产品的评价。
  • 地图底部四件事（1 分钟）：能否保存/调用经验、能否核验过程、能否连接适用工具、能否导出迁移资产。经验是律所的资产，不应锁死在某一个产品里。

问题 07

新技术带来困惑和恐慌，正常吗？

历史提供参照，不保证未来；总体向好时，个人损失也可能真实存在。
08 / 14

约 7 分钟（含网站 2—3 分钟）｜镜头后退，整张机器图向外泛起“回声”波纹；左右两张卡片各一组对照。

  • 开场：“新技术来时，困惑、焦虑甚至恐慌，在历史上很常见。今天只看两组对照。”
  • 第 1 组 岗位替代 ↔ 电话接线员：自动交换机推广后，接线员岗位大幅减少；整体就业后来转向文书、服务等行业，但当时在岗、年龄较大的接线员承受了真实冲击。相似在于“标准化环节被自动化”；不同在于 AI 碰到的是写作、检索、分析这类认知工作，覆盖面更广、扩散更快，而律师工作还包含责任与信任。
  • 第 2 组 技术投入 ↔ 生产率回报滞后：常说的“生产率悖论”——1987 年索洛说计算机随处可见，唯独生产率统计里看不到；经济史研究也指出，工厂电气化要等厂房布局、工作方式重新设计后，生产率才明显提升。相似：投入先行、回报滞后、要重组流程。不同：这次重组的是知识工作和组织习惯，滞后多久没人能保证。
  • 底线两句：历史是参照，不是保证；“社会整体变好”和“某些个人受损”可以同时成立。
  • 打开网站（需联网），首屏为动画，向下滚动进入内容区，按“组织”分类筛选（入口以现场页面为准），只点这两组卡片。
  • 注意：不引用“95% 失败”之类数字；网站标题“历史不会重复，但会押韵”常被归于马克·吐温，但出处未经证实，现场不要署名。
  • 过渡：“面对变化，我们具体能做什么？接下来是五项行动。”

成果很漂亮，就代表我会了吗？

判断 · 解释 · 复现 · 识别差异——个人基础能力与人机协作能力，都要培养。
09 / 14

约 5 分钟｜地图长出最外的“人”一圈：一份“漂亮的成果”从核验流向人，左下四个检查点依次点亮。从本页起，镜头逐步离开机器，走向人和组织。

行动二沉淀规则和数据

一项任务结束，应该留下什么？

材料是事实，规则是方法——分层存放，避免互相污染。
10 / 14

约 6 分钟｜外圈（即工作区）整体亮起，向右展开成一张工作区卡片，光点把留下的东西送进卡片。

  • 工作区卡片（与“工作区”一课呼应）：一个独立工作区里放着 agents 规则文件、memory 记忆文件、Skill 与脚本——这些是可复用的方法；另有原始材料与来源（只读、标来源日期），以及结果/反馈/测试样本（每次产出、修改意见、脱敏样本）。
  • 为什么分开：材料是事实，规则是方法，混在一起会互相污染——某个案子的特殊安排可能被当成通用规则。
  • 卡片下半“留下”：任务结束花 5 分钟做三件事——留下验证有效的规则；留一两份脱敏样本，以后用来测试；写清这条规则适用于什么情形、不适用于什么情形。
  • “不要”：客户的具体事实不进入通用记忆或通用规则。保密与合规优先，涉及客户信息按所内制度执行。
  • 现场可问：“你最近结束的一个项目，留下了哪条可以复用的规则？”

约 5 分钟｜客户来电出现在地图上方；机器中心写着 AI 能做的部分，人这一圈上方五个节点依次点亮。

  • 设定场景：AI 能很快整理往来记录、列出催告/谈判/诉讼等选项、起草律师函。
  • 逐一讲人的部分，最好用合伙人自己的经历举例：
    • 目标判断：客户嘴上说“起诉”，真正要的可能是尽快回款，或者保住长期合作。
    • 情境理解：行业惯例、对方是否资金困难、客户老板和法务之间的压力。
    • 利益取舍：诉讼成本、时间、关系、执行风险之间怎么权衡。
    • 沟通：同样的建议，什么时候说、用什么语气、先说哪一句。
    • 责任：最终意见由律师签字、承担执业责任。
  • 措辞要克制：不说“机器永远做不到”，技术在变；而是说在当下的职业与责任框架里，这些环节需要人来决定和承担。

约 5 分钟｜左侧三级依次出现；地图同步：①整个外圈（工作区）亮起 → ②“规则”外三道光圈依次点亮（写入 / 生效 / 健壮）→ ③规则、Skill、记忆、工具连成一线。与问题 05 区分：那页讲“一次纠正怎样沉淀”，本页讲“长期怎样让它越来越懂你”。

  • ① 基础（约 1.5 分钟）——先肯定：在一个固定的工作区里按方法使用，它有不断沉淀的机制（规则文件、Skill、记忆、样本都在同一个工作区里累积）。只要沿着这个方法用下去，它会越来越懂你。这是我们一直想传达的观念。
  • ② 再往上（约 2 分钟）——理解规则构建的逻辑：说清要求和理由后，知道怎样触发它把要求记进规则（例如明确说“把这条记进本工作区的规则”）。然后通过结果倒推检测三件事：
    • 已写入？——打开规则文件，看这条要求在不在。
    • 已生效？——开一个新任务，看输出是否真的遵守。
    • 够健壮？——隔一段时间、换个场景、换个模型，用行动二留下的脱敏样本复查。
      所以“懂你”是有套路和方法的。
  • ③ 再进阶（约 1.5 分钟）——人要更了解 Agent 及其扩展特性：规则、Skill、记忆、工具各管什么、什么时候被加载。了解了这些，才知道怎样把沉淀机制用得更好——这也是我们开这门课的原因。
  • 过渡：“个人能做到这三层，组织怎样让更多人做到？最后一项行动。”

约 7 分钟讲述 + 10 分钟交流｜交流就停在本页进行。地图底部出现组织“土壤”，一株株“个人尝试”从土里长出、开花，金线连到最外一圈——“组织的力量”。

  • 核心逻辑（约 4 分钟，左侧自下而上读）：
    • 01 让组织里更多人提高对 AI 本质和逻辑的认识——这正是这六节课在做的事。
    • 02 积极尝试使用，不等“完美方案”。
    • 03 在使用中不断发现与自己工作场景的结合点——结合点往往由一线的人自己找到，而不是自上而下指定。
    • 04 不断输入、迭代：把规则、样本沉淀下来（呼应行动二、行动四）。
    • 05 在组织内推广，持续提高成员的 AI 使用能力，百花齐放。
    • 06 组织通过机制提供数据、资源去激励——组织是“土壤”，个人的尝试汇聚起来，才形成组织的力量。
  • 怎么看效果（约 2 分钟）：不只看“用了多少次”，更要看重复劳动有没有减少、遗漏和返工有没有减少、别人能不能直接复用这套规则和样本。
  • 呼应全课（约 1 分钟）：个人层面是问题 04 的 Harness，组织层面是“土壤”——数据、资源、激励机制。
  • 交流（10 分钟）：出示问题，邀请 3—4 位合伙人各用 1—2 分钟回答：谁已经找到了结合点？组织能提供什么数据、资源和激励？讲师记录要点。时间不够可压缩到 2—3 位。
  • 交流结束后再翻到封底致谢。
