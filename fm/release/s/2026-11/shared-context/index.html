03第 002 期产品与技术11.09官方逐字稿锚定

多 Agent 各聊各的，哪些东西要存进共同的地方？

工具天天换，他们先把各自的产出收到同一个地方。

观点

歸藏提醒，今天这个工具好用、明天换另一个，如果不把属于自己的那部分留下来，用过的上下文就会丢掉。

歸藏 · 38:01 · 发言人观察

「因为很多时候都是封闭的嘛，你还是得要自己的那部分。因为每天都在变，这今天这个好用，明天那个好用，然后你一用就都丢了，其实也不好。」

这是他给跨工具使用的实践提醒，不是对某一款产品的评测。

杨攀认为，无论是工作任务还是个人资料，都应该让不同 Agent 共同沉淀到一个地方。

杨攀 · 38:08 · 发言人主张

「就是因为我们现在这个阶段也是要跨 Agent 再去用的。对你在这个 Agent 这儿，对吧，有些信息，那个，其实应该让他们共同沉淀到一个地方。」

主播对现阶段用法的判断，不是让所有 Agent 共享全量资料的建议。

故事

歸藏说自己把 Codex、Dots、Grok Bot、Muse、Claude Code 和 DeepSeek Harness 的上下文都劫持到同一个 GitHub 库，生产结果和聊天过程都回到自己的库里，而不走各工具自己的存储。

歸藏 · 38:17 · 当事人回忆

「对，我现在是都在 GitHub 里，然后我会给他分角色……它们几个都在一个上下文环境里工作。就是我会把它上下文劫持掉。然后把所有的上下文都连到我那个上下文部分去。然后所有的生产结果和聊天过程都回到我那库里。然后不会走它自己那个。」

当事人自己的工作方法。稿中的产品名依官方逐字稿照录。

新鲜事实

向阳乔木把个人资料放在 Notion；杨攀也说自己正在把收口做到 Notion。橘子的概括是：找个地方就行。

向阳乔木、 杨攀、 橘子 · 36:40 · 发言人观察

「比如我个人那些东西，现在我上期不说了嘛，我就放在 Notion 里。就是 Notion 无论是你说文本的，还是数据库表格什么的，对，我会放到那。」

这是几个人各自的收口选择，不是对 Notion 作为唯一方案的推荐。

人物与产品

讨论里出现的工具包括 Notion、GitHub，以及歸藏点名的 Codex、Claude Code、DeepSeek Harness 等。他们把 Super Agent / Personal Agent 带来的中间层，说成需要一块可累积的存储或个人数据库。

杨攀 · 35:57 · 发言人主张

「因为你现在是，你看到要不就是你最终的作品，要么就是看到的原来你聊天的会话。就是有了 Super Agent 这个东西之后，需要一个，对吧，中间的一个这个存储也好，上下文也好。」

对产品形态的现场讨论，不是已发布的产品规格。

应用启示

给跨工具记忆做一个最小实验：只共享同一项目的任务编号、已验证决定、依据和最后进度。角色、账户授权和不该跨项目流动的资料保持分离，再测更换模型后能否接手。
