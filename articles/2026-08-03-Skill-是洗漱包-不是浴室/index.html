Skill 是洗漱包，不是浴室

本文目录 一、先把公道话说足：Skill 确实是好东西 二、三个结构性短板：Skill 装不下的东西 第一个短板：Skill 没有积累 第二个短板：Skill 没有编排，也没有路由 第三个短板：迁移性悖论，这一点最锋利，也最少有人说 三、Skill 热的利益结构：谁在为这场热闹买单 四、浴室与洗漱包：重新定义 Skill 的位置 五、认真对待反方：Skill 不是"只是提示词" 六、收个尾

最近的法律科技圈，Skill 成了一个硬通货。

英文圈有人整理了一个叫 Awesome Legal Skills 的开源合集，一口气收录 139 项法律专用技能，号称覆盖合规、合同审查、法律翻译，主流 Agent 工具都能加载。中文圈也出现了"面向法律人的 Skills 集合"这类项目，宗旨写得很直白：沉淀并分发面向法律工作者的 AI 技能。连 Anthropic 自己都下场了：今年 5 月发布了一份 21 页的《Claude for the legal industry》部署手册，把自家法务团队的四条工作流公开为示范教材：合约红线从几小时压到几分钟，隐私影响评估从两小时缩到三十分钟。

做产品的在堆 Skill 库，做投资的在问"你们的 Skill 有多少个"，做竞品的在比"谁的 Skill 覆盖面广"。

先交代一下我自己的立场坐标：我有 106 个 Skill。我不是站在门外泼冷水的人，我可能是国内法律人里 Skill 最多的人之一。

但也正因为在门里面，我越来越确定一件事：这轮 Skill 热里，大多数人搞错了一个根本问题——Skill 到底是什么，以及，它到底不是你的什么。

一、先把公道话说足：Skill 确实是好东西

冷思考的前提是诚实。如果只挑毛病不提价值，那不是思考，是酸。

Skill 的第一重价值，是它是目前最成熟的"蒸馏器"。做法律科技的 Zack Shapiro 有一个概括我很认可：一个好的 Skill 不是一段提示词，而是一套包含分析框架、风险权重、表达风格和验证机制的指令集。换句话说，它能把"一个资深律师怎么审一类合同"这件事固化成一个可以反复执行的文件：先看什么、后看什么、什么条款要什么权重、什么情况必须停下来。把业务端口的标准作业方法，蒸馏成技术端口的可执行资产。这件事本身是有价值的，而且价值不小。

第二重价值在加载机制上。Skill 的官方设计里有一个核心原则叫渐进式披露，说白了就是很懂事的"按需加载"：平时只占一行书签的位置——名字加一句话说明，模型扫一眼知道"什么时候该翻你"；真派上用场了才翻开正文；正文里提到的附件材料，用到哪页查哪页。不像有些做法，不管你用不用得上，几千行说明先一股脑塞进上下文里。这个设计是精巧的。

第三重价值是它的接口属性：边界清晰、接口稳定、容易迁移、容易共享、容易版本化、容易测试。一份 Skill 写好，可以在网页端、命令行、开发接口里多处运行，甚至跨厂商通用。作为分发一个标准作业程序（SOP）的最小单位，它几乎是现成的最佳形态。新人入职，不用懂什么提示词工程，加载即用。

这里我还要修正我自己过去的一个说法。我之前写过一篇《Skill 祛魅》，说 Skill 的本质就是一个 md 文件。这话要补充一句：Skill 不只是一个 markdown 文件，它还可以捆绑脚本、模板、数据。Anthropic 内部分享过他们跑的几百个 Skill，反复强调的就是"Skill 是文件夹，不只是文件"。确定性的活让脚本干，判断性的活让模型干，这个分工是对的。

好话说完了。但请注意一个区分——"封装格式优秀"和"它是你的资产"，是两回事。 上面夸的每一条，夸的都是"封装格式"。而 Skill 热真正的问题，恰恰藏在后面。

二、三个结构性短板：Skill 装不下的东西

第一个短板：Skill 没有积累

我每次调用一个 Skill，它都是从零开始的。它不记得上次审这家客户的合同时发现了什么，不记得这个项目上次卡在哪个条款，不记得上周那次判断为什么翻车。

听起来像个小毛病，其实打在要害上。因为法律工作里最值钱的东西，恰恰不是"流程"，而是决策记录：为什么这个客户最终接受了 20% 的责任上限，为什么我坚持把那个看似标准的付款条款删掉，为什么这个项目我宁可放弃固定总价也要争一个调价机制。这些"为什么"，是一个律师年复一年攒下来的真正的本钱。

而一个 Skill 的文件结构里，没有一个位置是放这个的。它装的是"怎么干"，装不下"当时为什么这么定"。Skill 是消耗品式的能力，每次用完即归零；工作区是复利式的能力，每一次使用都在为下一次积攒利息。这个差别，用一天看不出来，用三年就是鸿沟。

第二个短板：Skill 没有编排，也没有路由

这一点我去年在另一篇文章里详细论证过，这里只说结论：Skill 是扁平的，要么全局要么项目，中间没有层；Skill 之间互不通气，审合同的 Skill 发现了风险条款，不会自动喂给下游的风险评估。一百个零件散在地上，不等于一辆车。

更要命的是路由的缺失。一个成熟律师的工作方式是层层下钻的：这是哪个客户，他有什么历史偏好；这是哪类合同，这类合同有什么专属坑；这是哪个项目，前几轮是怎么谈的。路由到最后，才真正开始干活。而触发一个 Skill 靠的是什么？名字和简介里的关键词匹配。它不知道客户是谁，不知道项目前史，它只是被一个叫"合同审查"的词唤醒了。

第三个短板：迁移性悖论，这一点最锋利，也最少有人说

Skill 最被吹捧的优点是"迁移便利"。但请你顺着这个优点往下想一步：一个 Skill 要能迁移，前提是什么？

前提是它必须抽象掉具体环境。一个能在任何人电脑、任何项目、任何客户场景下运行的合同审查 Skill，必然不包含你的客户习惯，不包含你的历史决策，不包含你的条款库，不包含你的项目背景，因为这些东西换一个环境就失效。可迁移性这个东西，天生排斥私有上下文。

于是就有一个悖论：能被装进 Skill 里四处流转的，永远是你方法论里"最不值钱"的那部分。不是因为它写得不好，是因为"可被公共化"本来就是它的设计前提。你的方法论是一个金字塔，能蒸馏进 Skill 的是底座，那些同行想想也能想到的标准动作；蒸馏不出去的是塔尖，你的客户知识、你的判断权重、你踩过的坑，这些才是真正构成壁垒的部分。

能被蒸馏的是你的方法，蒸馏不出去的是你的壁垒。记住这句话，下一节要用。

三、Skill 热的利益结构：谁在为这场热闹买单

想清楚了"能蒸馏的是底座"，再回头看这轮 Skill 热，很多事情就通透了。

先看厂商侧的账。对模型厂商和垂类应用厂商来说，Skill 简直是完美的资产收集器：每多一个高质量的法律 Skill 被分享出来，他们的产品在某个业务领域的基础表现就增强一分。收集成本是多少？几乎是零。不用谈判，不用付费，用户自己会打磨好了传上来，还自带传播热情。天底下没有比这更划算的蒸馏生意了。

这不是猜测，官方动作就摆在那里。Anthropic 把 Skills 做成了开放标准，让一次编写可以到处运行；又专门发布了那份 21 页的法律行业部署手册，把自家法务的工作流公开出来当教材。行业顾问 Rudy DeFelice 对手册的定位说得直白：Claude 不再只是垂直工具底下的模型，而是"工作得以完成的基础设施"。

请注意"基础设施"这三个字。这是一切平台的标准剧本：先把路修好，让大家把生意都搬到路上来，路本身就成了最值钱的资产。我不认为这是阴谋。这是教科书级的平台战略，过去二十年每一轮平台扩张都是这么打的，而且客观上确实降低了整个行业的起步门槛。但法律人至少要知道，这场交易里自己付出的是什么。

行业里其实有明白人。手册发布前后，Lawtrades 的策略长有个流传很广的比喻：Claude 的插件加连接器是一把多功能瑞士刀，预算有限的团队一把刀能应付八成场景，但"想切牛排还是得换刀"。The LegalTech Fund 的 Zach Posner 说得更直接：基础模型厂商大概能做到法律工具八成的功能，剩下最难的两成，留给垂直厂商。

把这句话翻译到律师个人身上，就是上一节那个结论：能被做成 Skill 分发的是那八成，可标准化的部分；剩下两成蒸馏不出去的，恰恰是你的壁垒。 厂商很清楚这个边界在哪，所以他们放心大胆地鼓励你分享。怕的是你自己不清楚。

再算用户侧的账。收益是真的：别人蒸馏好的作业标准，拿来就能用，起步门槛大降。代价有两个。一个是显性的：你分享出去的 Skill 越通用，就越成为所有用户，包括你的竞争对手，都能加载的公共基础设施。分享增强的是整个品类，稀释的是你的相对竞争力。另一个是隐性的，也是我更担心的：热度过高造成认知错配，法律人把"做 Skill"当成了"建能力"的全部，每天忙着攒洗漱包，忘了家里还没有浴室。

最后补一个实务提醒，和利益无关，和安全有关。Skill 是可以捆绑可执行脚本的，Anthropic 官方自己就警告过：恶意的 Skill 可能引入漏洞，可能把你的数据导向外部。律师的电脑里装的是什么？客户的保密信息、案件的未公开材料。从技能市场随手装一个来路不明的"精英律师"，跟把一个陌生人的 U 盘插进案卷库，区别没有想象的那么大。

四、浴室与洗漱包：重新定义 Skill 的位置

说了这么多短板，Skill 到底应该摆在什么位置？我用一个生活里的比喻。

你的工作区和 Skill 的关系，有点像家里的浴室和出门用的洗漱包。

浴室是一个长期存在、不断调整的生活环境。里面不只有牙刷牙膏，还有每个家庭成员的专属物品、各自的摆放位置、使用习惯、补充记录，和一套谁都能找到东西的取用规则。它随着日常生活不断丰富，也能根据不同人和不同场景，自动拿出需要的东西。

Skill 是一只洗漱包。包里的用品可能和浴室里的完全相同——牙刷可以是同一把牙刷——但它经过了筛选、组织和标注：什么时候用、带什么、怎么用、什么算用完，都明明白白。它的价值不是用品本身更强，而是边界清晰、拿起就走，也容易交给别人用。

这个比喻把两者的关系说透了：差别从来不在内容，在于一个是长期积累的环境，一个是标准入口的封装。 用技术一点的话说：Skill 是接口，像 API；工作区是系统，像操作系统。

而且我可以负责任地说：Skill 能做的，一个成熟的工作区全都能做——按需加载，规则文件可以做到；SOP，工作流文件可以做到；工具调用、脚本、模板，工作区都有对应的位置；记忆和规则进化，Skill 反而没有。反过来，工作区能做的——分层路由、客户知识、状态传递、决策积累——Skill 一样都做不到。这不是哪个更好的问题，是两者根本不在同一层。

我自己的系统是个现成的例子。不算机密，只说结构：106 个 Skill，底下垫着 27 个全局规则文件、约 4500 行行为约束、22 个项目工作区、54 个项目级规则，外加上万篇知识库文章、跨会话的经验记录、独立沉淀的个人方法论。那 106 个 Skill 只是整个系统最上面的一层——标准入口层。

做一个思想实验：把我那 106 个 Skill 全部拿走，我的系统照常运转，无非是少了一些顺手的入口；但如果把底下的规则层抽走，106 个 Skill 立刻变成一盘散沙。每一个都还能单独跑，但没有一个知道该为谁跑、按谁的口径跑、跑完交给谁。

旅行确实需要洗漱包。但没有人会把"我有一个洗漱包"当成"我有一个家"。

五、认真对待反方：Skill 不是"只是提示词"

写到这里，必须认真回应一下反方，不然这篇文章就是自说自话。

反方最有力的说法是：你把 Skill 说浅了。Anthropic 内部跑几百个 Skill，人家的经验是 Skill 能装脚本、数据、参考代码、模板；Zack Shapiro 也说了，那是指令集不是提示词。你口中的"工作区才能做的事"，人家一个组织良好的 Skill 也能做到大半。

这话在能力层面是对的，所以我在第一节就做了自我修正。但请顺着往下想：Skill 里能装脚本，工作区里有 scripts 目录；Skill 里能放模板，工作区里有模板库；Skill 里能塞参考数据，工作区里有整个知识库。能力清单逐项对下来，没有一项是 Skill 独有的。

所以"Skill 是不是只是 markdown"根本是个岔题。真正的问题只有一个：你的能力体系，住在哪。

住在 Skill 里，它是便携的、可分发的——同时也是公共的、不积累的。住在工作区里，它是私有的、持续积累的、每天都有利息进账的。这两个住所没有高下，只有分工：出门带洗漱包，回家过日子。怕的是把全部家当都塞进洗漱包里，还以为自己置业了。

六、收个尾

有人会问：那你还写 Skill 吗？

写，照写，照用，也照分享。洗漱包出门确实方便，而且说实话，分享 Skill 对行业是有真实贡献的——让更多人起步快一点，这件事值得做。我反对的从来不是 Skill，是把 Skill 当成能力的终点。

我自己的做法是分账：Skill 是消耗品预算，花出去不心疼；工作区是固定资产，每天收工前真正花心思的是另一件事——今天的工作里，有哪些判断、哪些"为什么"，值得留进我的浴室。一个条款为什么让步，一个策略为什么调整，一个客户为什么是这个偏好。这些东西进不了任何 Skill，但三年之后，它们就是我和任何一个拿着同样 106 个 Skill 的人之间的全部差别。

Skill 热会过去的，洗漱包会过时的，浴室是你每天要回去的地方。
