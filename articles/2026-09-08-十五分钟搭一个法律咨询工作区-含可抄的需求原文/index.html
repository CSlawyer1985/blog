十五分钟搭一个法律咨询工作区（含可抄的需求原文）

本文目录 第一步：把需求说出来 第二步：跑一个真实问题 目录结构长这样 两个容易忽略的机关 它会顺手帮你做成一件事：咨询档案 局限说在前面

解决什么问题：日常法律咨询的处理总是散的——问题来自微信、电话、邮件，答案发出去就没了，检索过程不留痕，年底想复盘今年都答过什么，无从下手。

这篇文章给出我实际在用的方案：一个会自动归档、自动查知识库、自动核验法条出依据的“法律咨询工作区”。搭起来要多久？口头说三分钟需求，agent 建结构加跑通第一个真实咨询，前后一刻钟左右。适合任何已经用上支持工作区和规则文件的 agent 工具的法律人。

第一步：把需求说出来

新建一个工作区，把下面这段话完整丢给 agent（按自己的情况改动措辞）：

以后我所有的法律咨询工作都在这个工作区处理。当我提出一个法律问题，或者丢给你一份咨询相关的材料时，你自动做四件事。第一，在工作区里新建一个专项文件夹，用“日期加问题总结”的方式命名。第二，文件夹里分三个子目录：输入放问题和原始材料，过程放你的检索和分析留痕，输出放最终结论。第三，结论性文件必须是 Word 文档。第四，凡是涉及法律依据的研究，必须先查我的本地知识库，并且严格按知识库的效力分级标识来引用；知识库没有的内容，用核验工具到商用法律数据库核对后再写进结论。

没有本地知识库的话，第四条可以先删掉，不影响前三条落地。但建议迟早补上——咨询质量的上限就在这条里。

第二步：跑一个真实问题

结构建好别空着验收，直接丢一个真实咨询进去。我在课上用的是这个：

请帮我查询一下哪些财产是夫妻共同财产，列出具体的法律依据。

正常情况下，agent 会依次做完：新建“2026xxxx_夫妻共同财产”文件夹；把问题归入输入目录；拆解问题、检索知识库、逐条核对法条现行效力；把带依据的解答写成 Word 文档放进输出目录。你要做的只是最后打开那份 Word。

跑完这一次，这个工作区就算交付了。以后每个咨询都是同一条流水线。

两个容易忽略的机关

没接数据库工具，它为什么也会去核验法条？我在演示这个工作区的时候，那个 agent 里并没有接法律数据库的插件，它照样自动完成了核验。原因在别处：知识库的规则文件里写了“引用前必须核验”，而本机的用户级规则里登记了核验工具的接入方式。agent 从跨工作区的记忆里找到了知识库位置，从用户级规则里找到了核验路径。这件事的启示是：你的配置是分层的，工作区没配的东西，用户级配置可能已经兜底了。反过来，遇到“它怎么知道”的疑惑，先翻用户级规则和记忆文件。

输出格式要前置写死，别让它自由发挥。第一版需求里没写输出格式的话，agent 可能现场给你写段代码生成文件——能用，但每次生成的文件样式都可能不一样，而且平白多一层出错机会。把“结论性输出必须是 docx，用某某工具生成”写进第一版需求，它就直接调用现成工具。需求里写死的每一条，都是少一个变量。

它会顺手帮你做成一件事：咨询档案

这套结构跑上一年，会积累上百个按日期和问题归档的文件夹。年底让 agent 扫一遍，今年答过的咨询集中在哪些领域、哪类问题反复出现、哪些可以沉淀成文章或产品——答案就在你自己攒的数据里。

知识管理难，难在要人额外做功。这个方案里，归档是咨询流程的副产品，你一次都不用专门去“整理”。

局限说在前面

三个诚实的提醒。一，它处理的是“标准型咨询”，事实复杂、需要深入案件分析的咨询仍然要进你的案件工作流，别混用。二，知识库和核验工具的质量决定输出上限，规则写得再好，底层资料是错的，结论照样错。三，给客户的正式解答发出前，法条和结论务必人工复核——流程自动化的是整理和归档，不是你的执业判断。
